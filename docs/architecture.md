# 技术选型与目录设计

## 平台目标

- 微信小游戏
- 抖音小游戏

这两个平台都更适合走“一套游戏主工程 + 平台适配层”的方案，而不是分别维护两套前端项目。

## 建议技术路线

### 1. 游戏客户端

建议使用 `Cocos Creator`。

原因：

- 对微信小游戏支持成熟，文档和社区资料相对完整。
- 支持发布到多个小游戏平台，更适合你现在的目标。
- 你有 Unity 和 C# 经验，上手节点、组件、场景这些概念不会太陌生。
- 比直接手写小游戏前端更省时间，尤其适合你目前前端经验偏弱的情况。

### 2. 后端服务

建议单独作为 `apps/backend`。

当前实现语言使用 `Go`，Web 框架使用 `Gin`，默认数据库使用 `SQLite`，ORM 使用 `Gorm`。

适合承载：

- 排行榜
- 用户基础数据
- 活动配置
- 广告位和开关配置
- 素材版本配置

不建议一开始做太重：

- 不做支付
- 不做复杂商城
- 不做多人实时对战

### 3. 平台能力封装

平台 API 差异不要散落在游戏代码里，统一收口到 `packages/platform-sdk`。

典型内容：

- 激励视频广告
- 插屏广告
- 登录
- 分享
- 存档
- 平台能力检测

## 推荐目录

```text
apps/
  backend/
  game/

packages/
  game-config/
  platform-sdk/

tools/
  art/

docs/
```

## 建议开发顺序

1. 先做核心玩法原型。
2. 再接广告位和平台能力。
3. 后端只提供最小必需接口。
4. 美术资源最后统一替换成成品图。

## 第一版玩法建议

先不要做太大，建议只做一个 1 分钟内就能玩明白的循环：

- 小鸡角色持球
- 点击或长按控制投篮
- 连续命中触发表情梗图变化
- 失败后结算分数
- 看广告复活一次

这个方向更适合广告变现，也更适合小游戏传播。
